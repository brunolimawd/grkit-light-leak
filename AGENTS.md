# Working on Light Leak

This is the source of truth for the unofficial **Light Leak** module for
[GRKit](https://github.com/ahonn/grkit). The former integration branch in
the `brunolimawd/GRKit` fork is an archive, not a second place to maintain
the module. Developing or building this repository does not require a
sibling checkout.

## Upstream references

- [GRKit's current contributor rules](https://github.com/ahonn/grkit/blob/main/CONTRIBUTING.md).
  Consult these when planning contributions to GRKit.
- The tested SDK revision is in [`GRKIT_REV`](GRKIT_REV). At that revision
  see [Writing a module](https://github.com/ahonn/grkit/blob/61dd9a697668d809939c2a75d402d76e418ff6fc/docs/modules.md),
  the [module contract](https://github.com/ahonn/grkit/blob/61dd9a697668d809939c2a75d402d76e418ff6fc/docs/module-reference.md),
  and the [icon guidelines](https://github.com/ahonn/grkit/blob/61dd9a697668d809939c2a75d402d76e418ff6fc/docs/icon-guidelines.md).
  Prefer the pinned docs for compatibility questions. If reviewing newer
  behavior, read the same documents at the candidate revision.
- Follow this repository's [contribution instructions](CONTRIBUTING.md)
  for its CI and independent releases. Don't add this module to the
  official GRKit package or modify GRKit itself as part of module work.

## Module invariants

- Keep the module ID and card file `LITLEAK.GRM`. Saved setting keys and
  their value IDs are compatibility contracts. Do not renumber or reuse
  them silently. Match changes to UI values across all five files in
  `text/`. Bump `module.toml`'s version for a new release.
- `light_leak.c` resolves style, side, strength and variation once per
  encode. Keep the main JPEG and its previews on the same draw. Do not
  call the firmware clock or introduce mutable cross-shot RNG state:
  older builds with the clock and shared state restarted on camera.
- `slit.c` and `reference.c` evaluate the effect at native sample centers.
  Do not replace them with an enlarged image mask. Preserve crop edges,
  clipped highlights and monochrome behavior. Keep scratch allocations
  within the SDK budget and keep validation at least as strong as
  `test.c`. Variation 1 is the original look.
- `indicator.c` paints only in the full-information still viewfinder.
  Preserve the ADJ artwork unless the change calls for it. `badge_art.h`
  is generated by `tools/generate-badge.rs`; do not hand-edit it. The
  `tiles/` PNGs are the checked-in ADJ source artwork. The viewfinder
  overlay does not use a native status slot and can hide the native grid.
- Stock images were visual references only. Do not add those images,
  watermarks, stock-derived raster assets, firmware, or build outputs.

## Verify changes

1. Use `grkit module test --dir .` and build an ARM `.GRM` in a fresh
   ignored `build/` directory. See [CONTRIBUTING.md](CONTRIBUTING.md) for
   sanitizer, generated artwork and installer checks.
2. Test hardware behavior for changes to capture, memory, or drawing.
   Record the actual body, firmware and what was tested. The only
   hardware configuration recorded at the first standalone release is
   **RICOH GR III, firmware 2.10**.
3. Use Conventional Commits. Keep release notes user-facing. Attach
   `LITLEAK.GRM` to a release rather than committing it.
